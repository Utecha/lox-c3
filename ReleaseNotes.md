# Release Notes

The goal of the latest rewrite of the project is not only to continue having the
project work with current versions of the C3 compiler. It is also to bring down
some features and improvements from the Wren language.

It will still be Lox in the end, however certain internal functions and data
structures will be different from the original implementation for one reason
or another.

## Lox Version 0.0.2

- Added the `lox` and `lox::memory` modules.
- Added the `LoxConfig` type to the `lox` module. This will contain
configuration data and function pointers for the VM to make use of.
- The VM's config takes a pointer to a `LoxReallocFn` for handling the actual
allocation of memory. This allows for it to be replaced with a different allocator
function.
- Added a custom `next_power_of_two` macro to remove the need to import
`std::math` in several places just for that macro.
- Added the `lox::array` generic module for generically typed dynamic arrays
managed by the VM's allocator.
- Added the `lox::value` module. Jumped ahead and implemented the NaN boxed
variant of the `Value` type, as well as the early start of objects as the
`Chunk` has been removed and inlined into the `ObjFun` type.
- Added the `lox::opcode` module which defines all of the supported
operation codes.
- Added the `lox::debug` module.

The totality of this initial build is effectively the first chapter of the book
plus a few addons/modifications to the original implementation.

## Lox Version 0.0.3

- Implemented the initial `lox::interpret` function as well as the `lox::execute` function,
which is invoked by `interpret` to execute the loaded bytecode.
- Added an associated value `stack_effect` to the opcodes. It represents the effect the given
instruction has on the stack (-1 pops a value, 0 does nothing, 1 pushes a value, etc.)
- Implemented several instructions early, as well as runtime error reporting. This patch is
effectively equivalent to Chapters 14, 15, and 18 completed, with a *very* small part of 19
and 23.
- Added the `debug::dump_stack` function for dumping the VM's stack during execution.
The original implementation just had the `TRACE_INSTRUCTIONS` flag for enabling its use.
Instead, there are now 2 flags: `TRACE_EXECUTION` and `DUMP_STACK`. The former will
dump the stack along with the disassembled instructions, following along the execution.
The latter dumps the stack only and skips the disassembled instructions.
- The bits added from Chapter 23 are the opcodes and interpreter support for the newly
added `AND` and `OR` instructions. These are dedicated jump instructions for the logical
operators which optimize them compared to the original implementation. In the original,
the logical OR was slower than the logical AND.

## Lox Version 0.0.4

### New Features

- Implemented the complete `lox::lexer` module as well as separate `lox::token` module.
- The `AND`, `NOT`, and `OR`, tokens are allowed as both keywords and operators.
- Added the `COLON` and `QUESTION` tokens for ternary operations.
- Added the `LBRACK` and `RBRACK` tokens for the to-be-added list objects (and
possibly statically sized arrays.)
- Added the `PERCENT` token for the modulo operator.
- Added the `BREAK` and `CONTINUE` keyword tokens for loops.
- Added the `STATIC` keyword token for defining static methods on classes.
- Added the `CONST` keyword token for defining immutable constants.
- Converted `main` to function as a basic CLI with a script runner and REPL.
- Modified the `lox::interpret` function to take in a pointer to source code
rather than a pointer to a function.
- Added `debug::dump_tokens` for dumping the tokens generated by the lexer.
- Added support for scientific notation for numeric literals (i.e. 3.14159E0).

### Fixes

- Fixed memory leak where the VM's value stack was not freed along with the VM.

## Lox Version 0.0.5

### New Features

- Implemented the complete `lox::compiler` module. This means there is now a
complete compiler to interpreter pipeline.
- Jump instructions are implemented early. The `LOOP` instruction is not
actually compiled yet. It is only supported in the VM.
- Conditional ternary (?:) operator implemented in full, making use
of the prevously mentioned jump instructions.
- Compiler can now view the next token coming up, rather than just the
current and previous tokens.
- Comparison & Equality operations are implemented early.
- Compiler tracks the expected number of stack slots a function will
use and stores it in the function. This is used to determine how large
of a stack to allocate.

### Fixes

- Fixed bug causing number Values to be incorrectly created with the NaN tagging
optimization enabled.

### Internal

- Removed temporary functions from `lox::value`.
- Moved to using separate functions for the bytecode debug dumping
per instruction type.
- Updated documentation accessible via `docs/docs.html`.

## Lox Version 0.0.7

### New Features

- Implemented string objects via the type `ObjString`. Strings are allocated
with flexible array members, which increases performance when allocating and
accessing a string as compared to the original implementation.
- Implemented the string hashing functions early.
- Added support for string concatenation.

## Lox Version 0.0.8

The major point of this release is the introduction of the new `ObjTable`
object. This replaces the old `Table` from the original implementation, which
allows for the inclusion of tables as a usable construct in Lox.

Each entry in a table is now a pair of Values for the key/value, rather than
an `ObjString *` for the key and a `Value` for the value.

As a result, it became a little bit more challenging to correctly intern
the strings. Even before making this change, there were issues that I
could not figure out that came about as a result of using flexible array
members for storing the string data.

Essentially, the *first* instance of a string equality operation, say
`"Hello" == "Hello"`, would result in a value of `false`, which in this
example is obviously not true (no pun intended.)

Using the REPL, you can immediately run that same code again under the
purview of the same LoxVM instance. Doing so would result in the correct value
of `true`. The struggle came down to figuring out *why* it would not work on
the first attempt, but would immediately after assuming you're in the same
instance.

As you can imagine, this meant that when running a script, which produces
a separate instance each time, the result would always be `false`.

However, it would strangely work on the first attempt, even when run from a
script, if you did a concatenation within the same expression:

```c
// Result: 'true'.
"Hello" + ", World!" == "Hello, World!"
```

All of that to say that strings are no longer interned, so each instance
of a string literal will always result in a new string object.

I feel like there is a way to make it work, but I have not yet figured it
out, and in all fairness, Wren made the same concessions for what I assume
are the same reasons.

### New Features

- Reimplemented the original `Table` into the new `ObjTable` type.
- All immutable Value types are now hashable and usable as keys/values in a
table.
- Jumped ahead a bit and implemented statements, in particular the expression
and `print` statements.

### Fixes
- Modified the `read_file` function in `main` to be more manual. Attempting to
run a script that was read using the `file::load` function would lead to strange
lexical errors about an unexpected character despite being at EOF.

### Internal

- Modified the `value::equals` function to reflect that of Wren's
implementation. This is largely due to the lack of string interning for
this implementation of Lox. My attempt to implement it while also having the
`ObjString` type use flexible array members proved challenging.

## Lox Version 0.0.9

### New Features

- Can define global variables, as well as read their value and assign to them.

### Fixes

- Removed the null check on the contract for the `table_find` function as it is
possible for it to be called with a null entries array, triggering a panic. The
capacity is checked before it executes in full so there wasn't much need for it.

### Internal

- Extended separators to 100 characters, and now allow comments and other code to
go up to the same limit. Results in less intense verticality and better output
for the doc comments when generating the docs.

## Lox Version 0.0.10

Mostly just bug fixes in this one, but there are a few new features introduced.

### New Features

- Added block statements wrapped in `{}`.
- Added support for local variables.

### Fixes

- Fixed bug in `table_find` where the index was not updated at all during
the probing of the table.
- Fixed missing opcode for `print` statements in the disassembler.
- Fixed a bug where freeing the VM's globals table when the length hit 0
would cause the VM to segfault when trying to free a function. Temporary
solution is to no longer do that until I can figure out the reason that
happens. The important part is that, according to valgrind, all memory is
ultimately being freed.
- Fixed minor bug where the functions `max_slots` value was uninitialized
on creation of a new function.
- Changed release builds to no longer emit debug-info as the `line-tables`
entry causes the C3 compiler to segfault when attempting to build.
- Adjusted the stack effects of several instructions that were incorrect.
For example, all of the binary operations had to be switched from 1 to -1,
as they pop 2 values (-2) and push one (+1) for a total of -1.

### Internal

- Converted `table_set` to return a boolean, returning `true` if the key
is newly added and `false` if it was pre-existing.
- Added new `GET_LOCAL` and `SET_LOCAL` instructions.
- Added a table of constants to the compiler directly to help de-duplicate
constant definitions.
